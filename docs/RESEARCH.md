## Audio technical conclusions

The [AudioWorklet API](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet) supports processing outside the main rendering thread and needs a secure context. OpenGuitar uses a lightweight capture worklet and a dedicated Worker for costly analysis. A 4096-sample frame at 48 kHz contains 85.33 ms of audio; fast DSP does not remove this acquisition delay.

The first implementation uses independently written YIN difference/normalization with interpolated period estimation. This has a small, understandable dependency surface and good measured synthetic behavior. Autocorrelation is a simpler candidate but needs careful octave/peak selection; McLeod/normalized square difference is a useful future comparison; FFT/chroma may help chord research but require harmonic disambiguation. These are engineering hypotheses, not measured comparative results. Only YIN has been benchmarked in this repository.

Confidence is a periodicity measure, not the probability that a learner played the requested string. Equal pitches can occur at multiple fretboard positions. Success means the measured pitch matches the target, not that a microphone proves finger placement. Simultaneous chord detection is deferred; the chord tool checks successive expected pitches.

## Original proposals implemented

Guitary is an original SVG guitar character with deterministic event responses. The studio palette, dashboard artwork, tab rendering, lessons, “Little lantern” phrase, “First light” timed melody, and point/combo presentation were created for this project. Focus and Play modes use one evaluator and shared local progress. No commercial tutoring API is required.

Personalization currently means selecting the next unpassed lesson and revisiting prior lessons. Adaptive skill models, full multi-module curriculum, production polyphonic recognition, richer games, and calibrated latency remain roadmap work.
